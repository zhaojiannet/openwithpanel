OpenWithPanel은 **기본 앱**을 관리하는 무료 오픈 소스 macOS 앱입니다. 파일 유형, 파일 확장자, 링크마다 어떤 앱으로 열지 하나의 윈도우에서 선택할 수 있습니다. 또한 Finder로는 할 수 없는 일도 해냅니다. `.env`, `.gitignore`, `Dockerfile`, `.npmrc` 같은 **확장자 없는 파일**의 기본 앱을 원하는 편집기로 지정할 수 있습니다.

## OpenWithPanel이 필요한 이유

macOS는 확장자 없는 파일 대부분을 `public.data`로 분류하며, 어떤 앱도 이 유형의 기본 앱이 되지 못하게 막습니다. Finder의 **정보 가져오기 › 다음으로 열기 › 모두 변경…** 기능은 이런 파일에 아무 효과가 없고, 명령줄 도구는 `-50` 오류로 실패합니다. Finder의 **항상 선택한 응용 프로그램으로 열기**는 선택한 파일 하나에만 적용됩니다.

그래서 무엇을 설정하든 `.env`, `.gitignore`, `Dockerfile` 같은 파일은 계속 텍스트 편집기로 열리거나 아예 열리지 않습니다. OpenWithPanel은 OpenWithPanel Helper라는 작은 도우미 앱으로 이 문제를 해결합니다. 자세한 내용은 [작동 방식](#작동-방식)을 참고하세요.

macOS가 다른 곳에서 빠뜨린 부분도 채워 줍니다. 새로 설치한 앱(대표적으로 Xcode)이 파일 연결을 가로채도 macOS는 알려 주지 않고, 원래대로 되돌리는 버튼도 없습니다.

## 기능

- **그룹별 기본 앱.** 파일 유형은 용도에 따라 텍스트, Markdown, 코드, 설정 및 데이터, 확장자 없는 파일, PDF, 문서, 이미지, 비디오, 오디오, 압축 파일로 묶여 있고, 그룹마다 앱 메뉴가 하나씩 있습니다.
- **한 번에 적용.** 그룹 전체의 형식을 하나하나 확인할 필요 없이 한 번에 설정하며, 몇 초 안에 반영됩니다.
- **형식별 예외.** 그룹을 펼쳐 `.md`나 `.py` 같은 형식 하나에 별도의 앱을 지정할 수 있습니다. 나중에 그룹의 앱을 바꿔도 예외는 그대로 유지됩니다.
- **확장자 없는 파일.** `.env`, `Dockerfile`, `.gitignore` 등 확장자 없는 파일을 원하는 편집기로 엽니다. 그 편집기가 이런 파일을 지원한다고 선언하지 않았더라도 마찬가지입니다.
- **사용자 지정 확장자.** 목록에 없는 확장자를 추가할 수 있습니다. `.go`, `.rs`, `.kt`, `.dart`, `.lua`처럼 macOS가 임시 유형으로만 인식하는 확장자도 포함됩니다.
- **링크의 기본 앱.** 웹 링크(`http`, `https`), 이메일(`mailto`), 캘린더 구독(`webcal`), 전화, 문자 메시지, FaceTime, SSH, FTP, 화면 공유를 열 앱을 선택하거나, **열지 않음**을 선택해 그런 링크를 클릭해도 아무 일도 일어나지 않게 할 수 있습니다.
- **확장자로 검색.** `py`나 `env`를 입력하면 해당 행으로 바로 이동합니다.
- **모든 파일 진단.** 파일을 끌어다 놓으면 왜 특정 앱으로 열리는지 확인하고, 그 자리에서 다른 앱을 고를 수 있습니다. 폴더를 끌어다 놓으면 개별 **다음으로 열기** 설정이 있는 파일을 찾아 지울 수 있습니다.
- **가로채기 알림.** 다른 앱(Xcode, 브라우저)이 설정해 둔 연결을 가로채면 OpenWithPanel이 배너를 표시하고, 클릭 한 번으로 되돌릴 수 있습니다.
- **실행 취소 및 복원.** 변경할 때마다 스냅샷을 저장합니다. `⌘Z`로 실행 취소하거나, 이전 스냅샷으로 복원하거나, OpenWithPanel이 아무것도 바꾸기 전 상태로 모두 되돌릴 수 있으며, 먼저 각 변경 사항을 미리 볼 수 있습니다.
- **폴더 규칙.** macOS 공식 API만 사용해, `~/Projects`처럼 지정한 폴더 안의 확장자 없는 파일이 편집기로 열리도록 설정하는 선택적 대체 방법입니다.
- **개발자 모드.** 파일 이름 패턴(예: `Dockerfile*`), 폴더, 텍스트/바이너리 내용에 따라 파일을 보내는 규칙, 각 앱이 선언한 유형과 순위를 포함한 진단의 전체 판정 과정, 프리셋 가져오기 및 내보내기.
- **깔끔한 제거.** 내장 제거 기능이 모든 연결을 원래 앱으로 되돌린 뒤 OpenWithPanel을 휴지통으로 이동합니다.
- **15개 언어.** 영어, 중국어 간체, 중국어 번체, 일본어, 한국어, 독일어, 프랑스어, 스페인어, 포르투갈어, 인도네시아어, 태국어, 베트남어, 아랍어, 러시아어, 힌디어를 앱 안에서 전환할 수 있습니다.

## 설치

macOS 26 Tahoe 이상이 필요합니다.

1. [Releases 페이지](https://github.com/zhaojiannet/openwithpanel/releases)를 열고 최신 릴리스의 **Assets**에서 `OpenWithPanel-<version>.dmg`를 다운로드합니다.
2. 다운로드한 DMG를 이중 클릭해 엽니다.
3. **OpenWithPanel**를 같은 윈도우에 보이는 **응용 프로그램** 폴더로 드래그합니다.
4. DMG를 추출한 다음 응용 프로그램 폴더에서 OpenWithPanel을 엽니다. 처음에는 macOS가 허용할지 묻습니다. [처음 실행하기](#처음-실행하기)를 참고하세요.

설치 프로그램이 없고 관리자 암호도 필요하지 않습니다.

**업데이트:** 새 DMG를 다운로드하고 OpenWithPanel을 다시 응용 프로그램 폴더로 드래그해 이전 버전을 대치합니다. 설정, 규칙, 스냅샷은 그대로 유지됩니다.

**제거:** [제거](#제거)를 참고하세요.

### 처음 실행하기

OpenWithPanel은 아직 Apple의 공증을 받지 않았기 때문에 처음 열 때 macOS가 차단합니다. 한 번만 허용하면 됩니다.

1. OpenWithPanel을 이중 클릭합니다. macOS가 OpenWithPanel을 확인할 수 없다고 하면 **완료**를 클릭합니다. 파란색 **휴지통으로 이동** 버튼은 클릭하지 마세요.

   <img src="../assets/first-launch-1.png" width="372" alt="첫 번째 경고: 완료 클릭">

2. **시스템 설정 › 개인정보 보호 및 보안**을 열고 **보안**까지 스크롤한 다음, OpenWithPanel 옆의 **그래도 열기**를 클릭합니다. 이 버튼은 1단계 이후 약 1시간 동안 표시됩니다.

   <img src="../assets/first-launch-2.png" width="560" alt="개인정보 보호 및 보안: 그래도 열기 클릭">

3. 로그인 암호를 입력하거나 Touch ID를 사용합니다. 이어서 나타나는 대화상자에서 **그래도 열기**를 한 번 더 클릭합니다.

   <img src="../assets/first-launch-3.png" width="372" alt="확인 대화상자: 그래도 열기 클릭">

이후로는 OpenWithPanel이 정상적으로 열립니다. 내장된 도우미도 함께 허용되므로 확장자 없는 파일을 열 때 더 이상 묻지 않습니다. DMG 안의 `First Launch.txt`에도 이 단계가 적혀 있습니다. 스크린샷은 영어 화면이며, 한국어 macOS의 버튼 이름은 위에 적은 것과 같습니다.

## 사용법

### 파일 유형 그룹

**파일 유형** 탭에는 모든 그룹이 카드로 표시됩니다.

| 그룹 | 포함 항목 |
|---|---|
| 텍스트 | `.txt` `.log` |
| Markdown | `.md` `.markdown` |
| 코드 | 많이 쓰이는 프로그래밍 언어, 아래 참고 |
| 설정 및 데이터 | `.json` `.yaml` `.toml` `.xml` `.ini` `.plist` `.csv` |
| 확장자 없는 파일 | `.env` `Dockerfile` `.gitignore` 등 |
| PDF | `.pdf` |
| 문서 | `.rtf` `.docx` `.doc` `.pages` `.odt` |
| 이미지, 비디오, 오디오, 압축 파일 | 각각의 일반적인 형식 |
| 사용자 지정 | 추가한 확장자 중 다른 어느 그룹에도 맞지 않는 것. 해당 항목이 있을 때만 표시 |

코드 그룹은 Stack Overflow 2025 개발자 설문조사에서 응답자의 5% 이상이 사용하는 언어를 다룹니다. JavaScript, TypeScript(`.tsx`), Python, Java, C, C++, C#, PHP, Ruby, Swift, Go, Rust, Kotlin, Dart, Lua, Shell(sh, bash, zsh), PowerShell, SQL, 어셈블리에 CSS, Makefile, JSX를 더했습니다. 다른 언어는 직접 추가할 수 있습니다. [확장자 추가](#확장자-추가)를 참고하세요.

### 그룹 전체에 앱 지정

카드 오른쪽의 메뉴에서 앱을 선택하면 그룹 안의 모든 형식이 그 앱으로 열립니다. 메뉴에는 macOS가 그 그룹을 열 수 있다고 판단하는 앱이 나열됩니다. **기타…** 항목을 선택하면 응용 프로그램 폴더에서 아무 앱이나 고를 수 있습니다.

### 형식 하나에 별도 앱 지정

그룹의 행이나 왼쪽 화살표를 클릭하면 펼쳐집니다. 형식마다 행이 있으며, 해당 파일의 시스템 아이콘과 확장자가 제목으로 표시됩니다. 행의 메뉴에서 다른 앱을 선택하면 그 형식은 이후 그 앱을 사용합니다. 해당 행에는 **개별 설정** 표시가 붙고, 그룹 행에는 개별 설정된 형식의 수가 표시됩니다.

- 별도 앱이 없는 형식은 메뉴에 회색으로 **그룹과 동일**이 표시됩니다.
- 형식이 다시 그룹을 따르게 하려면 메뉴에서 **그룹 설정 따르기**를 선택합니다.
- 나중에 그룹의 앱을 바꿔도 별도 앱이 있는 형식에는 영향이 없습니다.

형식이 8개를 넘는 그룹은 개별 설정했거나 직접 추가한 형식만 표시하고, 나머지는 아래쪽의 **형식 N개 모두 보기**로 볼 수 있습니다. 코드 그룹을 모두 표시하면 웹, 시스템 및 앱, JVM, 스크립트 및 셸 같은 섹션으로 나뉩니다.

### 검색

오른쪽 위의 검색 필드에 `py`나 `env` 같은 확장자를 입력합니다. 일치하는 그룹이 모든 형식과 함께 펼쳐지고 일치하는 행이 강조 표시됩니다. 어떤 그룹에도 없는 확장자라면 검색 결과에 **추가…** 버튼이 나타납니다.

### 확장자 추가

목록 아래쪽의 **확장자 추가…** 또는 검색 결과의 **추가…** 버튼을 사용합니다.

1. `nim` 같은 확장자를 입력합니다. 시트에 macOS가 그것을 무엇으로 인식하는지 표시됩니다.
2. OpenWithPanel이 이를 바탕으로 그룹을 제안합니다. 소스 코드는 코드로, 이미지는 이미지로, 인식되지 않는 것은 사용자 지정으로 갑니다. 다른 그룹을 고를 수도 있습니다.
3. **추가**를 클릭합니다. 해당 형식이 그 그룹에 **사용자 지정** 표시와 함께 나타나고 그룹의 앱을 따릅니다. 별도의 앱을 지정할 수도 있습니다.

이미 어떤 그룹에 있는 확장자는 두 번 추가되지 않으며, 시트에 어느 그룹에 있는지 알려 줍니다. 직접 추가한 형식의 행에는 제거 버튼이 있습니다.

### 적용

위의 모든 변경 사항은 먼저 대기 상태로 보관됩니다. 윈도우 아래쪽 막대에 대기 중인 변경 사항 수가 표시되며, **적용**을 누르면 반영되고 **버리기**를 누르면 취소됩니다.

- 파일 유형 변경은 확인을 묻지 않습니다. 형식을 몇 개 바꾸든 OpenWithPanel이 한 번에 시스템 환경설정에 기록하고 시스템이 한 번만 다시 읽게 하므로, 모두 몇 초 안에 반영됩니다.
- 링크와 웹 파일(`.html`)을 바꿀 때는 웹 브라우저를 바꿀 때처럼 여전히 시스템 대화상자에서 확인을 요청합니다. 브라우저를 몰래 바꾸는 것은 브라우저 하이재커가 하는 일이므로 macOS가 직접 물어야 합니다.
- 기록에 실패하거나(예: 권한 문제) 어떤 형식이 반영되지 않으면, OpenWithPanel은 시스템 API로 하나씩 다시 설정합니다. 이때 macOS는 새 앱을 사용할지 기존 앱을 유지할지 묻습니다. 기존 앱을 유지하면 OpenWithPanel은 그 형식을 해당 앱으로 개별 설정된 것으로 기록하고 이후로는 건드리지 않습니다.
- 적용 후 OpenWithPanel은 실제 시스템 상태를 다시 읽으므로, 목록에는 항상 실제로 반영된 내용이 표시됩니다.

### 실행 취소 및 복원

- **편집 › 실행 취소**(`⌘Z`)로 마지막 적용을 취소합니다. 여러 번 연속으로 취소할 수 있습니다.
- 도구 막대의 둥근 화살표 버튼은 **초기 상태로 복원**입니다. OpenWithPanel이 바꾼 모든 파일 유형과 링크를 OpenWithPanel을 처음 열었을 때 쓰던 앱으로 되돌립니다. 실행 전에 각 변경 사항이 나열됩니다.

macOS에는 파일 연결을 삭제하는 방법이 없고 다른 앱을 가리키게 하는 것만 가능하므로, 복원이란 각 유형을 스냅샷에 기록된 앱으로 다시 가리키게 하는 것입니다. 원래 macOS가 알아서 앱을 고르던 유형은 복원 후 같은 앱을 명시적으로 지정한 설정을 갖게 되며, 열리는 방식은 이전과 똑같습니다.

### 링크

파일 유형 아래의 카드에서 링크 종류별로 앱을 설정합니다.

| 행 | URL 스킴 |
|---|---|
| 웹 브라우저 | `http:` `https:` |
| 이메일 | `mailto:` |
| 캘린더 구독 | `webcal:` |
| 전화, 문자 메시지, FaceTime | `tel:` `sms:` `facetime:` |
| SSH, FTP, 화면 공유 | `ssh:` `ftp:` `vnc:` |

Mac에 있는 앱 중 하나라도 처리할 수 있는 종류의 링크는 모두 나열됩니다. 각 메뉴 맨 아래에는 **열지 않음**이 있습니다. 이것을 선택하면 어떤 앱에서든 그 종류의 링크를 클릭해도 아무 일도 일어나지 않습니다. 예를 들어 웹 페이지의 전화번호를 눌러도 전화가 걸리지 않게 할 수 있습니다. 되돌리려면 메뉴에서 다시 앱을 선택하면 됩니다. 웹 브라우저에 **열지 않음**을 선택하면 어떤 웹 링크도 열리지 않게 되므로 먼저 확인을 요청합니다. 스킴(예: `mailto`)이나 행 이름으로 검색할 수도 있습니다.

링크도 파일 유형과 똑같이 대기, 적용, 스냅샷, 실행 취소, 복원됩니다. 웹 브라우저를 바꾸면 시스템 대화상자에서 확인을 요청합니다. macOS 27에서는 `http`를 바꾸면 `https`도 함께 바뀌므로 OpenWithPanel이 `https`를 다시 설정하지 않아 한 번만 확인하면 됩니다.

## 진단

윈도우 위쪽의 **진단** 탭으로 전환합니다.

**이 파일은 왜 이 앱으로 열릴까요?** 점선 상자에 파일을 끌어다 놓습니다. 어떤 앱이 그 파일을 여는지와 그 이유가 표시됩니다.

- 파일에 Finder의 **정보 가져오기**에서 지정한 자체 **다음으로 열기** 설정이 있음
- OpenWithPanel Helper가 파일을 받아 규칙이나 그룹 설정에 따라 앱으로 보냄
- 이런 종류의 파일에 이 앱을 선택해 두었음
- 아무것도 설정되지 않아 macOS가 앱을 고름

결과 아래의 **대신 사용할 앱**으로 바로 다른 앱으로 전환할 수 있습니다. 파일에 자체 **다음으로 열기** 설정이 있으면 대신 **이 파일의 개별 설정 제거**가 나타납니다.

**자체 '다음으로 열기' 설정이 있는 파일 찾기.** 점선 상자에 폴더를 끌어다 놓습니다. OpenWithPanel이 그 안에서 자체 **다음으로 열기** 설정이 있는 모든 파일을 가리키는 앱과 함께 나열합니다. 파일을 선택하고 **개별 설정 제거**를 클릭하면 그 파일들은 해당 종류의 설정을 따르게 됩니다. 검사할 때 `.git`, `node_modules`, `.build`, `DerivedData`, `Pods`, `vendor`, `.venv`, `__pycache__` 폴더는 건너뜁니다.

**진단 보고서 내보내기.** 탭 아래쪽의 **진단 보고서 내보내기…** 버튼은 설정 내용, OpenWithPanel이 관리하는 각 유형을 현재 어떤 앱이 여는지, 이번 세션의 로그, 방금 진단한 파일을 담은 텍스트 보고서를 저장합니다. 문제를 신고할 때 개발자에게 보내 주세요.

## 설정

**OpenWithPanel › 설정…** 메뉴를 열거나 `⌘,`를 누릅니다.

**일반**

- **언어:** **시스템 설정 따르기** 또는 15개 언어 중 하나를 선택한 다음 **지금 다시 실행**을 클릭합니다. 적용하지 않은 변경 사항이 있으면 먼저 적용하거나 버리세요.
- **개발자 모드:** 더 자세한 정보를 표시합니다. [개발자 모드](#개발자-모드)를 참고하세요. 표시되는 내용만 바뀌고 설정은 절대 바뀌지 않습니다.

**폴더 규칙**

확장자 없는 파일에 쓰이는 방법이 더 이상 작동하지 않을 때를 위한 대체 방법입니다. 폴더를 추가하고 앱을 선택하면, OpenWithPanel이 그 폴더 안의 확장자 없는 텍스트 파일마다 그 앱을 가리키는 자체 **다음으로 열기** 설정을 지정합니다.

- 바이너리 파일과 직접 설정한 파일은 건드리지 않습니다.
- 새 파일은 OpenWithPanel을 열 때마다 처리되며, **지금 적용**으로 즉시 처리할 수도 있습니다.
- **모든 폴더 설정 취소**는 OpenWithPanel이 바꾼 모든 파일을 원래대로 되돌립니다.
- **건너뛸 폴더 이름**은 편집할 수 있습니다. 기본값은 진단의 폴더 검사에서 건너뛰는 폴더 목록입니다.

**기록**

적용할 때마다 저장한 스냅샷을 최신 순으로 최대 20개 나열합니다. 마지막의 **초기 상태(OpenWithPanel이 아무것도 변경하기 전)** 항목은 OpenWithPanel을 처음 열었을 때 기록된 상태입니다. 어느 것이든 **복원…** 버튼으로 복원할 수 있으며, 먼저 차이점을 미리 볼 수 있습니다.

**OpenWithPanel이 기록한 항목**

OpenWithPanel이 Mac에서 변경하거나 기록하는 모든 위치를 나열하며, 각각 **Finder에서 보기**가 있습니다.

- **파일 연결:** OpenWithPanel이 관리하는 항목(파일 유형과 링크)의 수
- **LaunchServices 환경설정 항목:** OpenWithPanel이 파일 유형(확장자 없는 파일 포함)을 위해 기록한 항목
- **OpenWithPanel Helper:** OpenWithPanel 앱 안에 있음
- **규칙 및 스냅샷:** `~/Library/Application Support/net.zhaojian.openwithpanel/`
- **파일별 ‘다음으로 열기’ 설정:** 폴더 규칙을 사용한 경우에만 있음

OpenWithPanel은 백그라운드에서 실행되지 않고, 로그인 항목이 없으며, 네트워크에 연결하지 않고, 데이터를 수집하지 않습니다.

### 제거

**OpenWithPanel이 기록한 항목** 아래쪽에서 **OpenWithPanel 제거…** 버튼을 클릭하고, 규칙과 스냅샷도 삭제할지 선택합니다. 그러면 OpenWithPanel은 다음을 수행합니다.

1. 바꾼 모든 파일 유형과 링크를 원래 앱으로 되돌립니다.
2. 폴더 규칙으로 지정한 파일별 설정을 모두 취소합니다.
3. 선택에 따라 `~/Library/Application Support/net.zhaojian.openwithpanel/`를 삭제하거나 유지합니다.
4. 자신을 휴지통으로 이동합니다.

파일 유형이나 링크를 하나라도 되돌리지 못하면(예: 시스템 확인을 거부한 경우) 제거가 중단되고 아무것도 삭제되지 않습니다.

규칙과 스냅샷을 유지하면 OpenWithPanel을 다시 설치했을 때 배너가 표시되고, 클릭 한 번으로 모든 설정을 되돌릴 수 있습니다. 앱을 휴지통으로 옮길 때 남은 파일을 삭제하는 앱 정리 도구는 유지하기로 한 규칙과 스냅샷까지 삭제할 수 있으므로, 그런 도구에서는 OpenWithPanel을 제외하도록 설정하세요.

대신 OpenWithPanel을 직접 휴지통으로 드래그하면 OpenWithPanel Helper도 함께 사라지고, macOS는 그것을 가리키던 연결을 버립니다. 다른 유형은 OpenWithPanel이 설정한 앱을 그대로 유지합니다. 이 경우 되돌리는 방법은 Application Support 폴더의 `UNINSTALL.txt` 파일에 설명되어 있습니다.

## 개발자 모드

**설정 › 일반**에서 켭니다. 켜면 다음이 추가됩니다.

- 각 형식 아래에 시스템 유형 식별자(UTI), OpenWithPanel Helper를 거치는 형식에는 **도우미** 배지
- 진단의 전체 판정 과정: 유형, 상위 유형, 텍스트인지 바이너리인지, 판정 결과, 그리고 파일을 열 수 있는 각 앱이 Info.plist에서 그것을 어떻게 선언하는지(일치하는 확장자나 유형, 역할, 순위)
- 기본 윈도우의 **규칙** 탭
- 설정의 **텍스트가 아닌 파일** 처리 방식과 **프리셋**

**규칙**은 OpenWithPanel Helper가 받은 파일을 어디로 보낼지 정합니다. 규칙은 다음으로 이루어집니다.

- 조건(최소 하나는 입력해야 함): 파일 이름 패턴(예: `Dockerfile*`, 대소문자 구분 안 함), 파일이 들어 있는 폴더(예: `~/Projects`), 내용이 텍스트인지 바이너리인지
- 적용할 유형. 기본값은 `public.data`(확장자 없는 파일)이며, 추가한 다른 유형도 OpenWithPanel Helper를 거치게 됩니다.
- 파일을 보낼 곳: 앱, **Finder에서 보기**, 또는 **원래 앱**

규칙은 위에서 아래로 확인되며 처음 일치하는 규칙이 적용됩니다. 드래그해서 순서를 바꿀 수 있고, 왼쪽 스위치로 규칙을 일시적으로 끌 수 있습니다. 규칙의 영향을 받는 그룹은 표준 모드에서 **규칙으로 제어됨**으로 표시됩니다.

**텍스트가 아닌 파일**은 OpenWithPanel Helper가 바이너리 파일을 어떻게 처리할지 정합니다. **Finder에서 보기**(기본값), **같은 앱으로 열기**, **원래 앱으로 열기** 중에서 고릅니다.

**프리셋**은 그룹 설정, 형식별 설정, 사용자 지정 확장자, 규칙을 JSON 파일로 내보내 다른 Mac에서 가져올 수 있게 합니다. 가져온 설정은 **적용**을 클릭하면 반영됩니다. 폴더 규칙과 원래 앱 기록은 Mac마다 다르므로 내보내지지 않으며, 가져올 때 덮어쓰이지도 않습니다.

## 작동 방식

OpenWithPanel은 앱 번들 안에 아주 작은 도우미 앱인 **OpenWithPanel Helper**를 담고 있습니다. 확장자 없는 파일에 쓸 편집기를 선택하면 OpenWithPanel은 `public.data`를 이 도우미로 지정합니다. 그런 파일을 열면 도우미가 규칙과 파일 내용을 확인해 텍스트 파일은 선택한 앱으로 넘기고, 바이너리 파일은 Finder에서 보여 준 뒤 종료합니다. 상주하지 않습니다. macOS는 전달할 파일이나 링크가 있을 때만 도우미를 실행하고, 도우미는 1초도 안 되는 유휴 시간 후 종료됩니다. 윈도우가 없고 Dock에도 나타나지 않습니다. **열지 않음**으로 설정한 링크도 도우미로 전달되며, 도우미는 그냥 무시합니다.

파일의 처음 8KB에 NUL 바이트가 있거나 올바른 UTF-8이 아니면 바이너리 파일로 간주합니다.

`.md`나 `.py`처럼 선택한 앱이 이미 지원하는 파일 유형은 도우미를 거치지 않고 그 앱에 직접 지정됩니다.

macOS는 `public.data`의 기본 앱을 설정하는 공개 API를 제공하지 않으며, macOS 26.4부터는 공개 API가 파일 유형을 하나 바꿀 때마다 확인을 요청합니다. 그래서 OpenWithPanel은 모든 파일 유형 변경 사항을 한 번에 LaunchServices 환경설정에 기록하고, `lsd` 서비스를 한 번만 재시작해 반영합니다. 이 방식은 Apple이 문서화하지 않았으며 시스템 업데이트 후 작동하지 않을 수 있습니다. 변경이 반영되지 않으면 OpenWithPanel은 확인을 요청하는 공개 API로 대체하며, 확장자 없는 파일에는 폴더 규칙을 대신 제안합니다.

## 자주 묻는 질문

**Mac에서 확장자 없는 파일의 기본 앱을 바꾸려면 어떻게 하나요?**
OpenWithPanel을 열고 **확장자 없는 파일**에 앱을 선택한 다음 **적용**을 누르세요. 이후 `.env`, `Dockerfile` 같은 파일이 그 앱으로 열립니다.

**Finder의 '모두 변경'이 `.env` 파일에 작동하지 않는 이유는?**
macOS는 이런 파일을 일반 데이터(`public.data`)로 취급하며, 공개 API로 이 유형의 기본 앱을 바꾸지 못하게 막습니다. OpenWithPanel은 도우미 앱으로 이 제한을 우회합니다.

**VS Code, Zed, Sublime Text를 코드 파일의 기본 편집기로 지정하려면?**
**코드** 그룹이나 개별 형식에 해당 편집기를 선택하고 **적용**을 누르세요. `.go`, `.rs`처럼 macOS 공식 유형이 없는 확장자도 지원됩니다.

**모든 것을 되돌릴 수 있나요?**
네. OpenWithPanel은 처음 실행할 때 원래 연결을 기록하며 그 기록을 절대 덮어쓰지 않습니다. **초기 상태로 복원**은 바꾼 모든 유형을 원래 앱으로 되돌립니다.

**OpenWithPanel이 데이터를 수집하거나 백그라운드에서 실행되나요?**
아니요. 네트워크에 연결하지 않고, 데이터를 수집하지 않으며, 백그라운드 에이전트를 설치하지 않고, 종료한 뒤 계속 실행되지도 않습니다. **설정 › OpenWithPanel이 기록한 항목**에서 기록하는 모든 위치를 확인할 수 있습니다.

**OpenWithPanel이 샌드박스를 사용하지 않는 이유는?**
macOS는 샌드박스 앱이 기본 앱을 바꾸는 것을 허용하지 않습니다. OpenWithPanel은 대신 강화된 런타임(hardened runtime)을 사용합니다.

## 알려진 제한 사항

- macOS에서 `.ts`는 비디오 형식(MPEG-2 전송 스트림)으로 인식되며, 이를 바꾸면 실제 비디오 파일에도 영향을 주므로 코드 그룹에는 TypeScript의 `.tsx`만 포함됩니다. 마찬가지로 `.r`, `.exs`, `.fs`는 macOS에서 각각 Rez 리소스, Logic 샘플러 파일, 셰이더로 취급되므로 코드 그룹에 없습니다.
- 파일 유형 설정은 문서화되지 않은 시스템 메커니즘에 의존하므로 시스템 업데이트 후 작동하지 않을 수 있습니다. 그런 경우 일반 파일 유형은 자동으로 시스템 API(유형마다 한 번 확인)로 대체되고, 확장자 없는 파일은 대신 폴더 규칙을 사용할 수 있습니다.
- macOS는 앱이 자기 프로세스의 로그만 읽도록 허용하므로 진단 보고서에는 OpenWithPanel Helper의 로그가 포함되지 않습니다. 필요하면 콘솔 앱에서 `net.zhaojian.openwithpanel`를 검색하세요.
- 인터페이스 번역은 아직 원어민의 검토를 거치지 않았습니다.

## 소스에서 빌드하기

Xcode 27이 필요합니다.

```sh
swift test --package-path OpenWithPanelKit
xcodebuild -project OpenWithPanel.xcodeproj -scheme OpenWithPanel build
```

DMG를 빌드하려면:

```sh
scripts/package.sh
```

결과물은 `.build/dist/`에 생성되며, `packaging/openwithpanel.rb`에 버전과 체크섬을 채워 만든 Homebrew cask도 함께 생성됩니다. 환경 변수를 설정하지 않으면 앱은 애드혹으로 서명되고 공증되지 않으며, 이때 DMG에 `First Launch.txt`가 포함됩니다. `DEVELOPER_ID`(Developer ID Application 인증서 이름)를 설정하면 그 인증서로 서명하고, `NOTARY_PROFILE`(`xcrun notarytool store-credentials`로 저장한 자격 증명 프로필)까지 설정하면 공증과 스테이플링을 수행합니다.

릴리스는 `.github/workflows/release.yml`의 GitHub Actions 워크플로로 빌드됩니다. 서명 방식과 릴리스 게시 방법은 [docs/release.md](../release.md)에 설명되어 있습니다.

## 프로젝트 구조

- `OpenWithPanelKit/`: 로컬 Swift 패키지. `OpenWithPanelCore`에 모든 로직이 있고, `OpenWithPanelPlatform`이 시스템 API를 감쌉니다.
- `Apps/OpenWithPanel/`: 메인 앱(SwiftUI).
- `Apps/Helper/`: 메인 앱 번들에 내장된 도우미.
- `scripts/`, `packaging/`: 패키징 스크립트와 Homebrew cask 템플릿.
