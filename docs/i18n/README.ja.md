OpenWithPanel は、**デフォルトの App** を管理するための無料・オープンソースの macOS アプリです。ファイルの種類、拡張子、リンクごとにどの App で開くかを、ひとつのウインドウで選べます。さらに、Finder にはできないこともできます。`.env`、`.gitignore`、`Dockerfile`、`.npmrc` のような**拡張子のないファイル**のデフォルト App を、お使いのエディタに設定できます。

## OpenWithPanel が必要な理由

macOS は拡張子のないファイルの大半を `public.data` に分類し、この種類のデフォルトにどの App も設定させません。Finder で**情報を見る › このアプリケーションで開く › すべてを変更…** と操作しても、これらのファイルには効果がなく、コマンドラインツールはエラー `-50` で失敗します。Finder の**常にこのアプリケーションで開く**は、選択した 1 つのファイルにしか適用されません。

そのため、何を設定しても `.env`、`.gitignore`、`Dockerfile` などのファイルはテキストエディットで開かれるか、まったく開けません。OpenWithPanel は OpenWithPanel Helper という小さなヘルパー App でこの問題を解決します。詳しくは[仕組み](#仕組み)を参照してください。

macOS がほかの場面で手当てしていない点もカバーします。新しくインストールした App（典型的には Xcode）がファイルの関連付けを奪っても macOS は知らせてくれず、元に戻すボタンもありません。

## 機能

- **グループごとのデフォルト App。** ファイルの種類は用途別にグループ分けされています（テキスト、Markdown、コード、設定とデータ、拡張子のないファイル、PDF、書類、イメージ、ビデオ、オーディオ、アーカイブ）。各グループに App メニューが 1 つあります。
- **まとめて適用。** グループ内の形式を 1 つずつ確認することなく一度に設定でき、数秒で反映されます。
- **形式ごとの例外。** グループを展開すると、`.md` や `.py` など 1 つの形式に別の App を指定できます。あとでグループの App を変更しても、例外はそのまま残ります。
- **拡張子のないファイル。** `.env`、`Dockerfile`、`.gitignore` などの拡張子のないファイルを、好きなエディタで開けます。そのエディタがこれらのファイルへの対応を宣言していなくても構いません。
- **カスタム拡張子。** 一覧にない拡張子を追加できます。`.go`、`.rs`、`.kt`、`.dart`、`.lua` のように、macOS が一時的な種類としてしか認識しない拡張子も含みます。
- **リンクのデフォルト App。** Web リンク（`http`、`https`）、メール（`mailto`）、カレンダー照会（`webcal`）、電話、テキストメッセージ、FaceTime、SSH、FTP、画面共有を開く App を選べます。**開かない**を選べば、そのリンクをクリックしても何も起きません。
- **拡張子で検索。** `py` や `env` と入力すると、該当する行に直接移動します。
- **どのファイルでも診断。** ファイルをドロップすると、なぜその App で開かれるのかがわかり、その場で別の App を選べます。フォルダをドロップすると、個別に**このアプリケーションで開く**が設定されたファイルを見つけて解除できます。
- **乗っ取りの通知。** ほかの App（Xcode、ブラウザ）が設定済みの関連付けを奪うと、OpenWithPanel がバナーを表示し、ワンクリックで元に戻せます。
- **取り消しと復元。** 変更のたびにスナップショットを保存します。`⌘Z` で取り消したり、過去のスナップショットに戻したり、OpenWithPanel が何も変更する前の状態にすべて戻したりできます。どれも事前に各変更をプレビューできます。
- **フォルダルール。** オプションの代替手段です。macOS の公式 API だけを使い、`~/Projects` など指定したフォルダ内の拡張子のないファイルをエディタで開くよう設定します。
- **デベロッパモード。** ファイル名のパターン（例: `Dockerfile*`）、フォルダ、テキストかバイナリかでファイルを振り分けるルール、各 App が宣言する種類とランクを含む診断の完全な判定チェーン、プリセットの読み込みと書き出し。
- **クリーンなアンインストール。** 内蔵のアンインストーラは、すべての関連付けを元の App に戻してから OpenWithPanel をゴミ箱に入れます。
- **15 言語。** 英語、簡体字中国語、繁体字中国語、日本語、韓国語、ドイツ語、フランス語、スペイン語、ポルトガル語、インドネシア語、タイ語、ベトナム語、アラビア語、ロシア語、ヒンディー語。App 内で切り替えられます。

## インストール

macOS 26 Tahoe 以降が必要です。

1. [Releases ページ](https://github.com/zhaojiannet/openwithpanel/releases)を開き、最新リリースの **Assets** から `OpenWithPanel-<version>.dmg` をダウンロードします。
2. ダウンロードした DMG をダブルクリックして開きます。
3. 同じウインドウに表示される**アプリケーション**フォルダに **OpenWithPanel** をドラッグします。
4. DMG を取り出してから、「アプリケーション」フォルダから OpenWithPanel を開きます。初回は macOS が許可を求めます。[初回起動](#初回起動)を参照してください。

インストーラはなく、管理者パスワードも不要です。

**アップデート：** 新しい DMG をダウンロードし、OpenWithPanel を再び「アプリケーション」にドラッグして古いものと置き換えます。設定、ルール、スナップショットはそのまま残ります。

**アンインストール：** [アンインストール](#アンインストール)を参照してください。

### 初回起動

OpenWithPanel はまだ Apple の公証を受けていないため、初めて開くときに macOS がブロックします。一度だけ許可してください。

1. OpenWithPanel をダブルクリックします。OpenWithPanel を検証できなかったと表示されたら、**完了**をクリックします。青い**ゴミ箱に入れる**ボタンはクリックしないでください。

   <img src="../assets/first-launch-1.png" width="372" alt="最初の警告：完了をクリック">

2. **システム設定 › プライバシーとセキュリティ**を開き、**セキュリティ**までスクロールして、OpenWithPanel の横にある**このまま開く**をクリックします。このボタンは手順 1 のあと約 1 時間表示されます。

   <img src="../assets/first-launch-2.png" width="560" alt="プライバシーとセキュリティ：このまま開くをクリック">

3. ログインパスワードを入力するか Touch ID を使います。続いて表示されるダイアログで、もう一度**このまま開く**をクリックします。

   <img src="../assets/first-launch-3.png" width="372" alt="確認ダイアログ：このまま開くをクリック">

これ以降、OpenWithPanel は普通に開けます。内蔵のヘルパーも一緒に許可されるので、拡張子のないファイルを開くときに追加の確認は出ません。この手順は DMG 内の `First Launch.txt` にも書かれています。スクリーンショットは英語の画面ですが、日本語の macOS でのボタン名は上に記したとおりです。

## 使い方

### ファイルの種類のグループ

**ファイルの種類**タブには、すべてのグループがカードとして並びます。

| グループ | 含まれるもの |
|---|---|
| テキスト | `.txt` `.log` |
| Markdown | `.md` `.markdown` |
| コード | よく使われるプログラミング言語（下記参照） |
| 設定とデータ | `.json` `.yaml` `.toml` `.xml` `.ini` `.plist` `.csv` |
| 拡張子のないファイル | `.env` `Dockerfile` `.gitignore` など |
| PDF | `.pdf` |
| 書類 | `.rtf` `.docx` `.doc` `.pages` `.odt` |
| イメージ、ビデオ、オーディオ、アーカイブ | それぞれの一般的な形式 |
| カスタム | 追加した拡張子のうち、ほかのどのグループにも当てはまらないもの。該当するものがあるときだけ表示 |

コードグループは、Stack Overflow 2025 開発者調査で回答者の 5% 以上が使っている言語をカバーします。JavaScript、TypeScript（`.tsx`）、Python、Java、C、C++、C#、PHP、Ruby、Swift、Go、Rust、Kotlin、Dart、Lua、Shell（sh、bash、zsh）、PowerShell、SQL、アセンブリに加え、CSS、Makefile、JSX です。そのほかの言語は自分で追加できます。[拡張子を追加](#拡張子を追加)を参照してください。

### グループ全体に App を設定

カードの右側にあるメニューから App を選ぶと、グループ内のすべての形式がその App で開かれます。メニューには、macOS がそのグループを開けると判断した App が並びます。**その他…** を選ぶと、「アプリケーション」フォルダから任意の App を選べます。

### 1 つの形式に個別の App を設定

グループの行、または左側の矢印をクリックすると展開されます。形式ごとに行があり、そのファイルのシステムアイコンと、タイトルとして拡張子が表示されます。行のメニューで別の App を選ぶと、以後その形式はその App で開かれます。その行には**個別に設定**の印が付き、グループの行には個別に設定された形式の数が表示されます。

- 個別の App がない形式では、メニューに灰色で**グループと同じ**と表示されます。
- 形式を再びグループに合わせるには、そのメニューで**グループに従う**を選びます。
- あとでグループの App を変更しても、個別の App を持つ形式には影響しません。

形式が 8 個を超えるグループでは、個別に設定した形式と自分で追加した形式だけが表示されます。残りは下部の **N 種類の形式をすべて表示**で一覧できます。コードグループをすべて表示すると、Web、システムとアプリ、JVM、スクリプトとシェルなどのセクションに分かれます。

### 検索

右上の検索フィールドに `py` や `env` などの拡張子を入力します。該当するグループがすべての形式とともに展開され、該当する行がハイライトされます。どのグループにもない拡張子なら、検索結果に**追加…** が表示されます。

### 拡張子を追加

一覧の下部にある**拡張子を追加…**、または検索結果の**追加…** を使います。

1. `nim` などの拡張子を入力します。シートに、macOS がそれを何として認識しているかが表示されます。
2. OpenWithPanel がそれに基づいてグループを提案します。ソースコードはコード、イメージはイメージ、認識されないものはカスタムです。別のグループを選ぶこともできます。
3. **追加**をクリックします。その形式は選んだグループに**カスタム**の印付きで表示され、グループの App に従います。個別の App を指定することもできます。

すでにいずれかのグループにある拡張子は重複して追加されず、シートにどのグループにあるかが表示されます。自分で追加した形式の行には削除ボタンがあります。

### 適用

ここまでの変更はすべて、まず保留されます。ウインドウ下部のバーに保留中の変更の数が表示され、**適用**で反映、**破棄**で取り消します。

- ファイルの種類の変更では確認を求められません。いくつの形式を変更しても、OpenWithPanel はシステムの環境設定にまとめて書き込み、システムに一度だけ読み込み直させます。すべて数秒で反映されます。
- リンクと Web ファイル（`.html`）の変更は、Web ブラウザを変更するときなどと同様に、引き続きシステムのダイアログで確認を求められます。ブラウザを黙って変更するのはブラウザハイジャッカーのやり方なので、macOS が直接ユーザに尋ねるべきだからです。
- 書き込みに失敗した場合（権限の問題など）や、ある形式が反映されなかった場合、OpenWithPanel はシステム API で 1 つずつ設定し直します。このとき macOS は、新しい App を使うか古い App のままにするかを尋ねます。古い App のままにした場合、OpenWithPanel はその形式をその App に個別に設定したものとして記録し、以後は変更しません。
- 適用後、OpenWithPanel は実際のシステムの状態を読み直すので、一覧には常に本当に反映された内容が表示されます。

### 取り消しと復元

- **編集 › 取り消す**（`⌘Z`）で直前の適用を取り消します。続けて何回でも取り消せます。
- ツールバーの丸い矢印のボタンは**初期状態に復元**です。OpenWithPanel が変更したすべてのファイルの種類とリンクを、初めて OpenWithPanel を開いたときの App に戻します。実行前に各変更が一覧表示されます。

macOS にはファイルの関連付けを削除する方法がなく、別の App に向け直すことしかできません。そのため復元とは、各種類をスナップショットに記録された App に向け直すことです。もともと macOS が自動で App を選んでいた種類には、復元後に同じ App を明示的に指定した設定が入ります。開き方は以前とまったく同じです。

### リンク

ファイルの種類の下にあるカードで、リンクの種類ごとに App を設定します。

| 行 | URL スキーム |
|---|---|
| Web ブラウザ | `http:` `https:` |
| メール | `mailto:` |
| カレンダー照会 | `webcal:` |
| 電話、テキストメッセージ、FaceTime | `tel:` `sms:` `facetime:` |
| SSH、FTP、画面共有 | `ssh:` `ftp:` `vnc:` |

Mac 上のいずれかの App が処理できる種類のリンクはすべて表示されます。各メニューの一番下には**開かない**があります。これを選ぶと、どの App でその種類のリンクをクリックしても何も起きません。たとえば、Web ページ上の電話番号で通話が始まらないようにできます。元に戻すには、メニューで再び App を選びます。Web ブラウザに**開かない**を選ぶと、Web リンクがまったく開かなくなるため、先に確認を求められます。スキーム（`mailto` など）や行の名前で検索することもできます。

リンクも、保留、適用、スナップショット、取り消し、復元のすべてがファイルの種類と同じように扱われます。Web ブラウザの変更はシステムのダイアログで確認を求められます。macOS 27 では `http` を変更すると `https` も変わるので、OpenWithPanel は `https` の再設定を省き、確認は 1 回で済みます。

## 診断

ウインドウ上部の**診断**タブに切り替えます。

**このファイルはなぜこの App で開くのか？** 破線の枠にファイルをドロップします。どの App で開かれるのか、その理由とともに表示されます。

- ファイル自体に、Finder の**情報を見る**で設定された**このアプリケーションで開く**の設定がある
- OpenWithPanel Helper がファイルを受け取り、ルールまたはグループの設定によって App に渡した
- この種類のファイルにこの App を選んでいる
- 何も設定されていないので、macOS が App を選んだ

結果の下にある**代わりに使う App** で、直接別の App に切り替えられます。ファイル自体に**このアプリケーションで開く**の設定がある場合は、代わりに**このファイルの個別設定を削除**が表示されます。

**個別に「このアプリケーションで開く」が設定されたファイルを探す。** 破線の枠にフォルダをドロップします。OpenWithPanel は、その中で個別に**このアプリケーションで開く**が設定されたすべてのファイルを、設定先の App とともに一覧表示します。ファイルを選んで**個別の設定を削除**をクリックすると、それらのファイルは種類ごとの設定に従うようになります。スキャンでは `.git`、`node_modules`、`.build`、`DerivedData`、`Pods`、`vendor`、`.venv`、`__pycache__` フォルダをスキップします。

**診断レポートを書き出す。** タブ下部の**診断レポートを書き出す…** で、設定内容、OpenWithPanel が管理する各種類を現在どの App で開くか、このセッションのログ、直前に診断したファイルを含むテキストレポートを保存します。問題を報告するときは、これを開発者に送ってください。

## 設定

**OpenWithPanel › 設定…** を開くか、`⌘,` を押します。

**一般**

- **言語：** **システムに従う**か 15 言語のいずれかを選び、**今すぐ再起動**をクリックします。未適用の変更がある場合は、先に適用するか破棄してください。
- **デベロッパモード：** より詳しい情報を表示します。[デベロッパモード](#デベロッパモード)を参照してください。変わるのは表示だけで、設定は変わりません。

**フォルダルール**

拡張子のないファイル向けの方法が使えなくなったときの代替手段です。フォルダを追加して App を選ぶと、OpenWithPanel はそのフォルダ内の拡張子のないテキストファイルすべてに、その App を指す個別の**このアプリケーションで開く**の設定を付けます。

- バイナリファイルと、自分で設定したファイルには手を付けません。
- 新しいファイルは OpenWithPanel を開くたびに処理されます。**今すぐ適用**ですぐに処理することもできます。
- **フォルダ設定をすべて取り消す**で、OpenWithPanel が変更したすべてのファイルを元の状態に戻します。
- **スキップするフォルダ名**は編集できます。初期値は、診断のフォルダスキャンでスキップするフォルダです。

**履歴**

適用のたびに保存されたスナップショットを、新しい順に最大 20 件表示します。最後の**初期状態（OpenWithPanel が何も変更する前）** は、初めて OpenWithPanel を開いたときに記録された状態です。どれも**復元…** で復元でき、事前に差分をプレビューできます。

**OpenWithPanel が書き込んだもの**

OpenWithPanel が Mac 上で変更・書き込みするすべての場所を、それぞれ **Finder で表示**付きで一覧表示します。

- **ファイルの関連付け：** OpenWithPanel が管理している項目（ファイルの種類とリンク）の数
- **LaunchServices の環境設定項目：** OpenWithPanel がファイルの種類（拡張子のないファイルを含む）のために書き込んだ項目
- **OpenWithPanel Helper：** OpenWithPanel App の中にあります
- **ルールとスナップショット：** `~/Library/Application Support/net.zhaojian.openwithpanel/`
- **ファイルごとの「このアプリケーションで開く」設定：** フォルダルールを使った場合のみ存在します

OpenWithPanel はバックグラウンドで動作せず、ログイン項目もなく、ネットワークに接続せず、データも収集しません。

### アンインストール

**OpenWithPanel が書き込んだもの**の下部で **OpenWithPanel をアンインストール…** をクリックし、ルールとスナップショットも削除するかどうかを選びます。OpenWithPanel は次の処理を行います。

1. 変更したすべてのファイルの種類とリンクを元の App に戻す
2. フォルダルールで行ったファイルごとの設定をすべて取り消す
3. 選択に従って `~/Library/Application Support/net.zhaojian.openwithpanel/` を削除または保持する
4. 自身をゴミ箱に入れる

ファイルの種類やリンクを 1 つでも元に戻せなかった場合（システムの確認を拒否したときなど）、アンインストールは中止され、何も削除されません。

ルールとスナップショットを残しておけば、OpenWithPanel を再インストールしたときにバナーが表示され、ワンクリックですべての設定を元に戻せます。App をゴミ箱に入れたときに残ったファイルを削除するクリーンアップツールは、残すことを選んだルールとスナップショットまで削除することがあります。そうしたツールでは OpenWithPanel を対象外にしてください。

代わりに OpenWithPanel を自分でゴミ箱にドラッグした場合、OpenWithPanel Helper も一緒に消え、macOS はそれを指していた関連付けを破棄します。ほかの種類は OpenWithPanel が設定した App のままです。その場合の戻し方は、Application Support フォルダ内の `UNINSTALL.txt` に書かれています。

## デベロッパモード

**設定 › 一般**でオンにします。次の内容が追加されます。

- 各形式の下にシステムの種類識別子（UTI）。OpenWithPanel Helper を経由する形式には**ヘルパー**のバッジ
- 診断の完全な判定チェーン：種類、親の種類、テキストかバイナリか、判定結果、そしてそのファイルを開ける各 App が Info.plist でどう宣言しているか（一致した拡張子または種類、役割、ランク）
- メインウインドウの**ルール**タブ
- 設定の**テキスト以外のファイル**の扱いと**プリセット**

**ルール**は、OpenWithPanel Helper が受け取ったファイルをどこへ送るかを決めます。ルールには次のものがあります。

- 条件（少なくとも 1 つは入力が必要）：ファイル名のパターン（`Dockerfile*` など、大文字と小文字は区別しない）、ファイルがあるフォルダ（`~/Projects` など）、内容がテキストかバイナリか
- 適用する種類。デフォルトは `public.data`（拡張子のないファイル）。追加したほかの種類も OpenWithPanel Helper を経由するようになります
- ファイルの送り先：App、**Finder で表示**、または**元の App**

ルールは上から順に照合され、最初に一致したものが適用されます。ドラッグで並べ替えられ、左側のスイッチでルールを一時的にオフにできます。ルールの影響を受けるグループには、標準モードで**ルールで制御**と表示されます。

**テキスト以外のファイル**では、OpenWithPanel Helper がバイナリファイルをどう扱うかを設定します。**Finder で表示**（デフォルト）、**同じ App で開く**、**元の App で開く**のいずれかです。

**プリセット**は、グループの設定、形式ごとの設定、カスタム拡張子、ルールを JSON ファイルに書き出し、別の Mac で読み込めるようにします。読み込んだ設定は**適用**をクリックすると反映されます。フォルダルールと元の App の記録は Mac ごとに固有なので、書き出されず、読み込み時に上書きされることもありません。

## 仕組み

OpenWithPanel は、App バンドルの中に小さなヘルパー App **OpenWithPanel Helper** を内蔵しています。拡張子のないファイル用のエディタを選ぶと、OpenWithPanel は `public.data` をこのヘルパーに向けます。そうしたファイルを開くと、ヘルパーはルールとファイルの内容を確認し、テキストファイルは選んだ App に渡し、バイナリファイルは Finder で表示してから終了します。常駐はしません。macOS は渡すファイルやリンクがあるときだけヘルパーを起動し、ヘルパーは 1 秒足らずのアイドル時間で終了します。ウインドウはなく、Dock にも表示されません。**開かない**に設定したリンクもヘルパーに送られ、ヘルパーはそれを単に無視します。

先頭 8 KB に NUL バイトが含まれるか、有効な UTF-8 でないファイルは、バイナリとみなされます。

`.md` や `.py` など、選んだ App がもともと対応しているファイルの種類は、ヘルパーを経由せずその App に直接割り当てられます。

macOS には `public.data` のデフォルト App を設定する公開 API がなく、macOS 26.4 以降は公開 API がファイルの種類を 1 つ変更するたびに確認を求めます。そこで OpenWithPanel は、ファイルの種類の変更をすべてまとめて LaunchServices の環境設定に書き込み、`lsd` サービスを一度だけ再起動して反映させます。この仕組みは Apple が文書化しておらず、システムのアップデートで使えなくなる可能性があります。変更が反映されなかった場合、OpenWithPanel は公開 API に切り替え、確認を求めます。拡張子のないファイルについては、代わりにフォルダルールを提案します。

## よくある質問

**Mac で拡張子のないファイルのデフォルト App を変更するには？**
OpenWithPanel を開き、**拡張子のないファイル**の App を選んで**適用**を押します。以後、`.env` や `Dockerfile` などのファイルはその App で開かれます。

**Finder の「すべてを変更」が `.env` ファイルに効かないのはなぜ？**
macOS はこれらを汎用データ（`public.data`）として扱い、公開 API を通じてこの種類のデフォルト App を変更することを禁じています。OpenWithPanel はヘルパー App でこの制限を回避します。

**VS Code、Zed、Sublime Text をコードファイルのデフォルトエディタにするには？**
**コード**グループ、または個別の形式にそのエディタを選び、**適用**を押します。`.go` や `.rs` のように macOS の正式な種類がない拡張子にも対応しています。

**すべて元に戻せますか？**
はい。OpenWithPanel は初回起動時に元の関連付けを記録し、その記録を上書きすることはありません。**初期状態に復元**で、変更したすべての種類を元の App に戻せます。

**OpenWithPanel はデータを収集したり、バックグラウンドで動作したりしますか？**
いいえ。ネットワーク接続も、データ収集も、バックグラウンドエージェントのインストールも行わず、終了後に動作し続けることもありません。**設定 › OpenWithPanel が書き込んだもの**に、書き込むすべての場所が表示されます。

**OpenWithPanel がサンドボックス化されていないのはなぜ？**
macOS はサンドボックス化された App にデフォルト App の変更を許可していません。OpenWithPanel は代わりに Hardened Runtime を使っています。

## 既知の制限

- macOS では `.ts` がビデオ形式（MPEG-2 トランスポートストリーム）として認識され、変更すると本物のビデオファイルにも影響するため、コードグループには TypeScript の `.tsx` だけを含めています。同様に、`.r`、`.exs`、`.fs` は macOS ではそれぞれ Rez リソース、Logic のサンプラーファイル、シェーダとして扱われるため、コードグループに含めていません。
- ファイルの種類の設定は文書化されていないシステムの仕組みに依存しており、システムのアップデートで使えなくなる可能性があります。その場合、通常のファイルの種類は自動的にシステム API（種類ごとに 1 回の確認）に切り替わり、拡張子のないファイルには代わりにフォルダルールを使えます。
- macOS では App が読めるのは自分のプロセスのログだけなので、診断レポートには OpenWithPanel Helper のログが含まれません。必要な場合は「コンソール」App で `net.zhaojian.openwithpanel` を検索してください。
- 画面の翻訳は、まだネイティブスピーカーによるレビューを受けていません。

## ソースからビルド

Xcode 27 が必要です。

```sh
swift test --package-path OpenWithPanelKit
xcodebuild -project OpenWithPanel.xcodeproj -scheme OpenWithPanel build
```

DMG をビルドするには：

```sh
scripts/package.sh
```

出力先は `.build/dist/` で、`packaging/openwithpanel.rb` からバージョンとチェックサムを埋め込んで生成した Homebrew cask も一緒に出力されます。環境変数を設定しない場合、App はアドホック署名され、公証されません。その場合 DMG には `First Launch.txt` が含まれます。`DEVELOPER_ID`（Developer ID Application 証明書の名前）を設定するとその証明書で署名し、さらに `NOTARY_PROFILE`（`xcrun notarytool store-credentials` で保存した認証情報プロファイル）を設定すると公証とステープルを行います。

リリースは `.github/workflows/release.yml` の GitHub Actions ワークフローでビルドされます。署名の方法とリリースの公開手順は [docs/release.md](../release.md)に書かれています。

## プロジェクト構成

- `OpenWithPanelKit/`：ローカルの Swift パッケージ。`OpenWithPanelCore` にすべてのロジックがあり、`OpenWithPanelPlatform` がシステム API をラップします。
- `Apps/OpenWithPanel/`：メイン App（SwiftUI）。
- `Apps/Helper/`：メイン App のバンドルに内蔵されるヘルパー。
- `scripts/`、`packaging/`：パッケージ用スクリプトと Homebrew cask のテンプレート。
